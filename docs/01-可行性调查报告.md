# 「免 token 诗词查询插件」可行性调查报告

> 调查日期：2026-05（基于对 [chinese-poetry-api](https://github.com/palemoky/chinese-poetry-api) 与 [poetry.palemoky.com](https://poetry.palemoky.com/) 的源码、文档阅读及线上接口实测）

---

## 一、调查对象

| 对象 | 说明 |
| --- | --- |
| GitHub 仓库 | [palemoky/chinese-poetry-api](https://github.com/palemoky/chinese-poetry-api)：Go 编写的中国古诗词 API 服务，开源，GPL-3.0 |
| 在线服务 | [诗泉 (poetry.palemoky.com)](https://poetry.palemoky.com/)：上述项目的官方在线实例，Cloudflare 托管 |
| 数据源 | 开源项目 [chinese-poetry](https://github.com/chinese-poetry/chinese-poetry)（GitHub 上最大的中文古诗文数据集之一） |

---

## 二、核心结论（先说答案）

> **结论：完全可行，且这个 API 是目前做「免 token 诗词插件」最合适的公共数据源之一。**
>
> 它天然满足「免 token」的全部要求：**免费、无需注册、无需申请 API Key、无鉴权头**，浏览器直接 fetch 即可（CORS 全开）。主要风险是**限流（20 次/分钟/IP）**与**单点依赖（个人维护、无 SLA）**，但这两点都有成熟的低成本对策（见第五节方案）。

---

## 三、逐项调查结果

### 3.1 「免 token」成立吗？—— 成立 ✅

- 官方 FAQ 明示：**完全免费且开源，无需注册或申请 API Key 即可直接调用**。
- 实测所有接口（`/api/stats`、`/api/poems/random`、`/api/search`、`/api/authors` 等）**不带任何 `Authorization` / `X-API-Key` 头**均返回 200。
- 唯一的"门槛"是 IP 限流，不是身份认证。

### 3.2 浏览器插件能直接调用吗？—— 能 ✅（CORS 全开）

- 实测响应头：`Access-Control-Allow-Origin: *`。
- 这意味着**浏览器扩展 / 网页 / 桌面 WebView 均可直接 fetch**，不需要代理、不需要服务端中转。
- 这对插件形态是决定性的利好：零后端、纯客户端即可完成。

### 3.3 数据量够用吗？—— 够 ✅

实测 `/api/stats` 返回：

```
poems: 371,313 首   authors: 13,577 位   dynasties: 11 个   types: 17 种
```

- 唐诗、宋词、元曲、诗经、楚辞、乐府诗、论语、四书五经等全收录。
- 五绝/七绝/五律/七律、宋词、元曲等体裁细分齐全。
- 每首诗词含：`id`、`title`、`content`（分行数组）、`author`、`dynasty`、`type` 结构化字段，适合做筛选与展示。

### 3.4 接口能力盘点（已实测）

| 能力 | 端点 | 实测结果 |
| --- | --- | --- |
| 健康检查 | `GET /health` | 200 ✅ |
| 数据统计 | `GET /api/stats` | 200 ✅ |
| 随机诗词 | `GET /api/poems/random` | 200 ✅，支持 `author` / `dynasty` / `type` / `char`（飞花令单字）过滤 |
| 全文搜索 | `GET /api/search?q=关键词&page=&pageSize=` | 200 ✅（搜索词要求 ≥2 个汉字，单字词返回 400） |
| 作者列表 | `GET /api/authors?page=&page_size=` | 200 ✅ |
| 朝代列表 | `GET /api/dynasties` | 200 ✅（含起止年份，可做年代轴） |
| 体裁列表 | `GET /api/types` | 200 ✅（含句数/每句字数元数据，可做格律校验） |
| 简繁切换 | 所有接口 `?lang=zh-Hans / zh-Hant` | 支持 ✅ |
| GraphQL | `POST /graphql` | **在线版未开放（404）** ⚠️，仅本地自建版可用 |

### 3.5 性能与稳定性（实测）

- **延迟**：10 次连续请求平均 **~140ms**，波动极小（138–152ms），对查询类插件完全可接受。
- **限流**：实测 25 次连续 `/api/stats` 请求出现 **4 次 429**（约合 20 次/分钟/IP），与官方文档一致：
  - 普通接口：20 次/分钟/IP
  - 搜索接口：8 次/分钟/IP
  - 429 响应带 **`Retry-After` 头**，客户端可据此做优雅退避重试。
- **可用性**：Cloudflare 托管 + HSTS，uptime 良好；但属于**个人维护项目，无 SLA 承诺**。

### 3.6 许可证合规

- 项目采用 **GPL-3.0**。
- **关键区分**：GPL 约束的是"复制/修改其代码"，而**插件只是作为 HTTP 客户端调用线上 API，不涉及代码分发，完全不受 GPL 约束**。
- 若后续采用"自建实例兜底"方案（直接 fork/部署该服务），则该实例需按 GPL-3.0 开源，但插件本体仍不受影响。
- 数据本身来自 MIT 友好的 [chinese-poetry](https://github.com/chinese-poetry/chinese-poetry) 数据集，用于展示/查询无版权障碍。

### 3.7 风险清单

| 风险 | 等级 | 说明 | 对策 |
| --- | --- | --- | --- |
| 限流 429 | 🟡 中 | 20/8 次每 IP 每分钟 | 客户端缓存 + 限速队列 + 退避重试 |
| 单点依赖 | 🟡 中 | 个人维护、无 SLA，可能停服/变更 | 多源兜底（见下） |
| 接口变更 | 🟢 低 | v0.6.0 起 REST 路径稳定 | 端点配置化，可一键切换 |
| 搜索词限制 | 🟢 低 | 单字搜索返回 400 | 输入 ≥2 字提示 |
| 隐私/合规 | 🟢 低 | 无鉴权即无用户数据收集 | 纯查询接口无隐私风险 |

## 四、多源兜底方案盘点（应对单点依赖）

「免 token」不等于"只能依赖一个免费公共 API"，插件设计上应预留**数据源抽象层**，按优先级降级：

| 优先级 | 数据源 | 说明 |
| --- | --- | --- |
| 1 | poetry.palemoky.com（公共在线） | 零成本、零维护，主数据源 |
| 2 | 本地内置离线数据包 | 将 chinese-poetry 常用子集（如全唐诗+宋词）打包进插件，完全离线可用、零限流 |
| 3 | 自建 Docker 实例（`palemoky/chinese-poetry-api`） | 数据全量 37 万首，部署一次永久免限流；需要一台小服务器 |
| 4 | 其他免费公共 API（如 [今日诗词 jinrishici](https://www.jinrishici.com/)、[古诗词网](https://gushiwen.cn)、[chinese-poetry 社区镜像](https://github.com/chinese-poetry/chinese-poetry)） | 备胎 |

> 注：离线数据包方案最稳——插件本质是"查询工具"，把数据带在本地后连网络都可以不要，且彻底绕开限流。

## 五、可行性综合评分

| 维度 | 评分（5 分制） | 说明 |
| --- | --- | --- |
| 免 token 达成度 | ⭐⭐⭐⭐⭐ | 无注册、无 Key、CORS 全开 |
| 数据覆盖 | ⭐⭐⭐⭐⭐ | 37 万首、1.36 万作者，主流古诗全有 |
| 接口能力 | ⭐⭐⭐⭐ | 搜索/随机/筛选/飞花令齐全；缺 GraphQL（在线版） |
| 性能 | ⭐⭐⭐⭐ | ~140ms 稳定延迟，够用 |
| 稳定性 | ⭐⭐⭐ | 个人维护无 SLA，需兜底设计 |
| 合规 | ⭐⭐⭐⭐⭐ | 调用无 GPL 义务，数据开源可查 |

**综合判定：可行性高（推荐实施）。** 建议采取「公共 API 为主 + 本地缓存 + 可选离线包/自建兜底」的架构，把唯一的中等风险（限流与单点）用低成本手段消化掉。
